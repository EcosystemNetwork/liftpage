# LiftPage security audit: 2026-11-18

Mode: Daily (8/10 confidence gate) · Scope: full · Branch: stack-migration (uncommitted work included)

## Stack
Next.js 16.3.2 App Router (server actions + route handlers) · npm · Supabase Postgres/Auth/Storage (service-role server client, RLS deny-all) · Supabase Auth sessions via @supabase/ssr · Stripe Checkout + webhook · Inngest jobs · Resend · PostHog · Sentry · social OAuth (X, LinkedIn, Instagram, YouTube, TikTok) · deployed on Netlify.

## Findings

### [HIGH] F-1: next 16.3.2 has critical/high advisories
Confidence 9/10 · Phase 3 / OWASP A03 · package.json
`npm audit --omit=dev`: next 16.0.0–16.4.4 is affected by GHSA-2464-fhr4-w9xw (unauth RCE in Image Optimization with SVG), GHSA-cjq9-62q9-8jv4 (image optimizer SSRF), GHSA-p3m5-59mp-jv5r (server action DoS; this app uses server actions), GHSA-mcj8-r9mp-w47p (cache poisoning), and others. `/_next/image` is served whether or not the app uses next/image.
Fix: `npm i next@16.4.6 eslint-config-next@16.4.6` (patch upgrade per npm), then build and test. Priority P0.

### [MEDIUM] F-2: safeNext() open-redirect bypass via tab/newline
Confidence 8/10 (the bypass is verified; reachability is conditional) · OWASP A01 · lib/dal.ts:64
safeNext blocks `//` and `/\` but not `/<TAB>/evil.com`. WHATWG URL parsing strips tabs and newlines, so `new URL("/\t/evil.com", origin)` resolves to `https://evil.com/`. Verified with Node.
Reachable at app/auth/confirm/route.ts:35 (after a valid token or code) and at the login server action redirect (app/actions/auth.ts:58) via `/login?next=/%09/evil.com`.
Exploit: phishing link to `/login?next=/%09/evil.com`. The victim signs in on the real site and lands on a lookalike page ("session expired, sign in again").
Fix: reject control characters and confirm the origin:
```ts
export function safeNext(value: unknown, fallback: string): string {
  if (typeof value !== "string" || /[\u0000-\u001f\\]/.test(value)) return fallback;
  if (!value.startsWith("/") || value.startsWith("//")) return fallback;
  const base = "http://x";
  return new URL(value, base).origin === base ? value : fallback;
}
```
Add a test case. Priority P1.

### [MEDIUM] F-3: No security headers (clickjacking on admin pages)
Confidence 8/10 · OWASP A02 · next.config.ts, proxy.ts
No CSP / frame-ancestors, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, or HSTS is set anywhere, and there's no netlify.toml. Admin pages with one-click server-action buttons (switch account off, reset password, publish) can be framed by another site.
Fix: add `headers()` in next.config.ts with `X-Frame-Options: DENY`, `Content-Security-Policy: frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, and HSTS. Priority P1.

### [LOW] F-4: inngest bundles vulnerable zod (<4.6.6)
Confidence 6/10 for exploitability (below the gate; listed because npm flags it as high) · package.json
GHSA-mrhx-c7xc-m3w5 (memory exhaustion on oversized collections). The Inngest endpoint verifies signatures, so attacker-controlled input is limited. npm's suggested fix (inngest 0.3.0) is wrong. Watch for an inngest release that bumps zod, or add an `overrides` entry for zod once one is compatible. Priority P3.

## Checked and clean
- Every admin route handler and admin server action goes through `adminOrResponse` / `requireAdmin`. Admin role is locked to the owner email in code (`effectiveRole`) and by a DB constraint.
- Client actions are scoped to `me.id` (metrics, review, messages, projects, change requests, export). No IDOR found.
- RLS is on for every table with no policies (deny-all for anon/authenticated). DB functions have EXECUTE revoked. Role never comes from user metadata.
- Stripe webhook: verified signature on the raw body, event dedupe, single-winner `paid_at` update, duplicate-payment refund. Prices are server-side only.
- OAuth connect: random state in an httpOnly cookie, compared in constant time, admin-only. Network tokens sealed with AES-256-GCM.
- Rate limits on login, signup, forgot-password, the request form, checkout, and messages. Signup and forgot-password don't reveal which emails have accounts.
- Email HTML is escaped. CSV export neutralises formula injection. Media uploads go through signed URLs with an allowlisted MIME type and a server-chosen path.
- Secrets: .env* is gitignored, and none are in git history (the only `sk_live_` hit is a test stub). .env.example has placeholders only.
- No CI workflows, no Dockerfile, no eval or innerHTML (the theme script is a static constant).
